Part 1 — Decision tenets and how we choose a platform

Why this page

There is no perfect platform; every option has cons. So before we compare Databricks, AWS-native or GCP, we write down what the data hub must guarantee, and what we are willing to trade. The platform that keeps the guarantees with the fewest trades wins. The guarantees come from the requirements (audit, PHI, evaluation, the CIS handshake), not from tool preference.

Tenets — what the hub guarantees, on any platform

  1. Nothing that feeds a decision is ever overwritten. Reruns create versions; corrections are new rows. Bronze, silver, the truth graph and gold are append-only.
  2. Every decision can be reproduced, years later. Each gold row carries its version keys: rule snapshot digest and fingerprint, graph version, model, CCDM and taxonomy versions, feed version. Replay from bronze with the same versions gives the same answer.
  3. Every piece of evidence has a source. A code points to a graph fact, the fact to a sentence (page and offsets) in silver, the sentence to the ZIP in bronze, the rule to its PRM snapshot and guideline page. No hop is inferred at audit time.
  4. PHI is read by jobs, not people. Pipeline, components and the Explain API read PHI tables; humans get masked views unless they are auditing. Every PHI location has its own key and its own role.
  5. Other systems come through the doors. Lookup and Explain APIs, or the S3 handoffs. Nobody reads our tables directly, and we never write to PRM; PRM is the policy store of record and we keep a copy.
  6. Same input plus same rules gives the same answer, and a rule change flips zero previously-correct charts. Both are release gates, checked against the golden dataset.
  7. Bad data is kept and reported, not dropped or fixed. Quarantine holds the row with a reason and an owner; the counts go back to CIS as a daily number.
  8. The data layer is portable; only the plumbing is platform-specific. Tables are Delta/Parquet on object storage, jobs are PySpark, paths and endpoints are configuration. Triggers, catalog, roles and the doors' endpoints are the only things that change with the platform.

Trade-offs we accept

  • A rebuild of the plumbing if the company's hyperscaler decision moves us; not a rebuild of the data layer.
  • A file handoff with the components for the demo instead of APIs.
  • Days of lead time for cross-account access and PHI approval, rather than sharing a bucket or a workspace.
  • The hub does not improve data quality. It keeps, flags and reports.

What does not change with the platform

The CIS contract, the six silver tables and quarantine, the truth graph store, the gold table, the golden dataset and replay job, the evaluation metrics, the policy copy, and the four rules in Part 2. All of it is being built now on Databricks against synthetic data and carries over.

Part 2 — Data blueprint: what the hub keeps, and why

This is the inventory of every kind of data in the data hub. One row per kind. For each: what it is in plain words, who writes it, who reads it, whether it holds PHI, how long we keep it, and where we are today.

Status: built = runs today on synthetic data · next = slice 2 · later = 2027.

Four rules that apply to every row

  1. We never overwrite anything that fed a decision. A rerun creates a new version; a correction is a new row. The old row stays.
  2. Every decision row records which versions produced it: the rule set, the truth graph, the model, the schema, the reference data. That is what lets us reproduce it years later.
  3. People don't read PHI tables; jobs do. The pipeline, the AI components and the Explain API read them. People see masked views, unless they are auditing.
  4. Nobody reads our tables directly. Other systems come through the two APIs (Lookup and Explain) or the S3 file handoffs. The policy rules live in PRM; we keep a nightly copy and never write back to it.

How it is organised

Every table is registered in the catalog with an owner, a PHI flag, a retention period, and the four rules as tags. One schema per lane: bronze, silver (ccdm), truth graph (ctg), gold, policy, reference, feedback.

The audit question, walked through

"Why did you recommend E11.22 on this chart in 2026?"

Gold row (verdict, which check, confidence) → the rule and rule-set version → the rule text and guideline page (policy copy) → the truth graph version → the evidence sentence, page and position (silver) → the original ZIP (bronze). Every hop is a kept, versioned row. Rerunning from bronze with the same versions gives the same answer. The audit package is this walk, frozen into one file.
